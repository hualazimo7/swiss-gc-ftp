## 13. SwissFTP：PC 端传文件到 SD 卡（2026-11-08）

需求是「PC 端连 Swiss 的 FTP 工具，用于传输文件给 SD 卡」。查源码确认
**Swiss 只有 FTP 客户端（`devices/ftp/`），没有 FTP 服务端**；PC→SD 的现成通路只有
httpd(80) 的 FatFs 端点。因此做成 FTP 风格的双栏客户端 + 一个可选的标准 FTP 网关，
**不改固件、不用刷 `IPL.dol`**。

### 13.1 新增文件（都在汉化工作区，未动上游源码）

| 文件 | 内容 |
|---|---|
| `tools/swiss_client.py` | 协议层：`/ls /upload /get /rm /rename /state`，UTF-8 percent-encode、流式上传下载、进度/取消、`RLock` 串行、错误解析 |
| `tools/swiss_ftp.py` | tkinter 双栏 GUI（浅色/深色磨砂主题）、传输队列、覆盖确认、日志、CLI |
| `tools/swiss_ftp_gateway.py` | 标准 FTP 服务端（PASV/EPSV、LIST/NLST/MLSD、RETR/STOR、SIZE、DELE、RNFR/RNTO），FTP 命令 → httpd 端点 |
| `tools/mock_swiss.py` | 照抄 httpd.c 的 `strstr`/`url_decode`/1024 字节请求头规则，供无实机自检 |
| `tools/启动 SwissFTP.bat` / `tools/启动 FTP 网关.bat` | 双击启动，走 `py -3`（开发环境内置 Python 无 tkinter） |

### 13.2 关键实现与踩坑

- 固件用一次 `net_recv(1024)` 读请求头 → 请求头必须一次 `sendall` 且 < 1000 字节；
  路径全部 percent-encode（`/rename` 必须是 `from=...&to=...`，固件 `strstr("&to=")`）。
- `/upload` 拼的是 `root + name`，`root` 必须带尾斜杠；`root[512]` 之前已从 8 字节修好。
- `GET /get` 成功是 `application/octet-stream` + `Content-Length`，失败是 `text/plain` 的
  `error: ...`；下载先写 `.part` 再 `os.replace`，避免留下半截文件。
- 卷按 `pick_upload_root` 顺序探测 `sdb:/ → sda:/ → sdc:/`；`/state` 的 `path=` /
  `selname=` 值可能含空格，解析要整行取值，`sel=N count=M` 才按空格拆。
- FTP `STOR` 是流式、事先无长度，而 `/upload` 必须有 `Content-Length` → 网关先缓冲整文件
  到本地临时文件再转发；`MKD`/`REST` 明确回 550（固件没有 mkdir / 不支持续传）。
- GUI 的 `ttk.Treeview` 不会自动收窄，列宽总和压到 399 以内，否则 125% DPI 下右栏被挤出窗口。
- 自检会污染 `~/.swissftp.json`：改为改本模块全局 `CONFIG_PATH`（脚本以 `__main__` 运行时
  `import swiss_ftp` 是另一个模块实例），且 `--mock` 不写回 host/port。

### 13.3 验证

`python tools/swiss_ftp.py --selftest` → **17/17 PASS**（协议 11 + 网关端到端 +
GUI 冒烟 5）。中文/空格文件名上传后回读 SHA-256 一致；`ftplib` 走网关的
STOR/RETR/LIST/RENAME/DELE 全过；CLI `--cli --gateway` 用独立进程验证可连。
浅色与深色界面均已截屏检查。

**实机未验证**：当时 `192.168.1.2:80` 能完成 TCP 握手但 `/`、`/state` 均无响应
（主机应还在游戏里，Swiss 已退出），UDP 33333 心跳也超时。等主机回到 Swiss
主界面后，用 GUI「连接」或 `swiss_ftp.py --cli --host 192.168.1.2 --ls sdb:/` 复测。

## 14. SwissFTP 打包成单文件 EXE（2026-11-08 18:35）

用户要求「要 exe 的程序」。用 Python 3.14 + PyInstaller 6.22.3 打成
`dist/SwissFTP.exe`（onefile + GUI 子系统，13.11 MiB / 13,743,851 B），
免装 Python，双击不弹控制台黑窗。

### 14.1 新增 / 修改

| 文件 | 内容 |
|---|---|
| `dist/SwissFTP.exe` | 成品，自带 Python 3.14 + tkinter/Tcl-Tk + 全部业务模块 |
| `tools/build_exe.py` | 一键打包：`--clean --onefile --windowed --icon --version-file`，显式 hidden-import `mock_swiss` / `swiss_client` / `swiss_ftp_gateway` / `ftplib`，排除 PIL/numpy/matplotlib/pytest |
| `tools/打包 EXE.bat` | 双击重建，固定用 `py -3` |
| `tools/make_icon.py`、`tools/assets/swissftp.ico` | 生成 16–256 七档图标（蓝底圆角 + 白色 SD 卡 + 蓝色上传箭头） |
| `tools/version_info.txt` | 构建时自动生成的内嵌版本资源（中文产品名/描述，1.0.0.0） |
| `tools/swiss_ftp.py` | 新增 frozen I/O 层、`--version`、`--log` |
| 两个 `启动 *.bat` | 改为优先调用 `..\dist\SwissFTP.exe`，EXE 不存在才回退源码 |

### 14.2 关键实现与踩坑

- PyInstaller `--windowed` 产物是 GUI 子系统，启动时 `sys.stdout/stderr` 为 **None**，
  任何 `print` 都会抛 `AttributeError`。加 `_NullWriter` / `_TeeWriter`：纯 GUI 模式吞掉输出，
  带 `--cli/--selftest/--version/...` 时用 `AttachConsole(-1)` 复用父控制台，
  失败则 `AllocConsole()`，再重定向到 `CONOUT$`。
- `--log FILE` 在 **argparse 解析之前**手动从 argv 扫描（否则 `--version`/`--help`
  的输出来不及写日志），所有模式都把 stdout/stderr tee 到文件，便于无控制台环境验证。
- 判断「要不要控制台」用显式开关白名单；只传 `--host` / `--theme` 仍算纯 GUI，不弹黑窗。
- `import mock_swiss`、`import ftplib` 等函数内导入必须写 hidden-import，否则 EXE 里
  `--mock` / `--selftest` 会 ModuleNotFoundError。
- 版本资源文件里的中文用 UTF-8；PE Subsystem = 2（GUI），图标资源组 1 个。

### 14.3 验证（全部直接跑 EXE，不是跑源码）

- `SwissFTP.exe --selftest --log ...` → **17/17 PASS**；`--protocol-selftest` → 12/12。
- `--version` → `SwissFTP 1.0 (单文件 EXE, Python 3.14)`；`--cli --ls sdb:/` 正常列目录。
- EXE 常驻 `--cli --gateway` 后，标准 `ftplib` 的 NLST/CWD/STOR（中文名）/RETR
  （SHA-256 一致）/SIZE/DELE 全过。
- GUI 无参启动只有 1 个 `TkTopLevel` 窗口，无 conhost/控制台窗口；深色界面截图完整。
- 把 PATH 清成只剩 `C:\Windows\System32;C:\Windows` 仍可运行；放在「中文 测试目录」
  下也可运行 → 不依赖系统 Python、不惧中文路径。
- 自检未污染 `~/.swissftp.json`；`FileDescription / ProductName / FileVersion` 版本资源正确。
